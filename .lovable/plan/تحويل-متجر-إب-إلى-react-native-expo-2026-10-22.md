# تحويل متجر إب إلى React Native + Expo

## الرأي والنتيجة المطلوبة
Expo مناسب إذا كان الهدف تطبيق iPhone وAndroid حقيقيًا بواجهة مصممة للجوال، وليس الموقع داخل غلاف. التحويل سيكون إعادة بناء للواجهات والتنقل والتعامل مع الهاتف، مع إعادة استخدام البيانات والقواعد المناسبة من التطبيق الحالي، لا تحويلًا آليًا لملفات React.

النتيجة: مشروع Expo كامل المصدر، وتعليمات تشغيل وبناء واضحة، وربط بنفس مشروع Supabase الحالي. لا أعد بأن التطبيق جاهز للنشر في المتاجر قبل التوقيع وإعداد تسجيل الدخول واختباره على أجهزة فعلية.

## طريقة التسليم وحدود المعاينة
- يبقى موقعك الحالي يعمل دون حذف أو تغيير أثناء التحويل.
- يُجهّز مشروع Expo مستقل، ويُسلّم كأرشيف مصدر نظيف قابل للتنزيل؛ لا يدخل الموقع داخل WebView ولا يستخدم Capacitor.
- معاينة Lovable الحالية مخصصة لمشروع الويب، وليست محاكي iPhone أو Android. اختبارات نسخة الويب من Expo، إن أمكن تشغيلها، لا تُعتبر إثباتًا لعمل وظائف الهاتف.
- ننقل جميع وظائف العميل والتاجر والإدارة؛ لا نكتفي بشاشات شكلية أو بيانات تجريبية ونطلق عليها «تحويل كامل».

## 1. تثبيت النطاق قبل النقل
إنشاء قائمة مطابقة للشاشات والوظائف الحالية، تشمل صلاحيات كل دور، الحالات الفارغة والأخطاء، والروابط بين الشاشات. توثيق كل وظيفة منقولة وما تم اختباره وما يحتاج جهازًا أو إعدادًا خارجيًا.

## 2. واجهة أصلية ومتسقة
- الحفاظ على هوية متجر إب: أيقونة المبنى الخطية دون خلفية دائرية، بألوان مناسبة للوضع الفاتح والداكن.
- العربية وRTL افتراضيًا، مع بنية ترجمة للإنجليزية؛ الأرقام والأسعار والتواريخ بأرقام لاتينية كما في النظام الحالي.
- شريط تنقل سفلي للعميل، ومسارات واضحة للتاجر والإدارة بحسب الصلاحيات.
- احترام المساحة الآمنة للشاشة ولوحة المفاتيح، والرجوع الأصلي والإيماءات وحجم الخط المفضل لدى المستخدم.
- أزرار لمس مريحة، تسميات لقارئ الشاشة، تباين مقروء، وتحميل تدريجي وأخطاء قابلة لإعادة المحاولة.
- البحث والفلاتر والإضافة والتعديل في شاشات وحوارات مناسبة للجوال؛ تأكيد العمليات المدمرة ومنع الضغط المتكرر أثناء الحفظ.
- فتح التطبيق على تجربة الاستخدام المناسبة لحالة الحساب، وليس صفحة تسويق.

## 3. الحساب وتسجيل الدخول
- البريد وكلمة المرور، Google، استعادة كلمة المرور، وتعديل الحساب.
- حفظ الجلسة بالطريقة المناسبة للهاتف، واستعادتها وتجديدها، والتعامل مع فتح روابط تسجيل الدخول واستعادة كلمة المرور.
- استكمال الاسم ورقم +967 الفريد والموقع قبل دخول الشاشات المحمية، مع معالجة رفض الإذن وإمكانية تسجيل الخروج.
- إبقاء إرسال OTP معطلًا؛ لا نعرض رقم الهاتف على أنه موثّق ما لم يثبته الخادم.
- ربط Google بحسابات Supabase الحالية، دون إنشاء نظام حسابات بديل.

## 4. جميع وظائف النظام
### العميل
الرئيسية، التصنيفات المتداخلة، البحث والفلاتر، تفاصيل المنتج، معرض الصور والتكبير باللمس، الفيديو، البيع والإيجار، العملات YER/SAR/USD، المفضلة المتزامنة، الاتصال وWhatsApp، الإشعارات الحالية، الحساب والخصوصية والشروط.

### التاجر
قائمة المنتجات، الإضافة والتعديل والحذف، رفع الوسائط، حقول التصنيف الديناميكية، إدارة الموظفين والصلاحيات المتاحة، وإعدادات التاجر.

### الإدارة
المستخدمون والأدوار والتجار، التصنيفات والتداخل والحقول الديناميكية، إدارة المنتجات، وكل إجراءات الإدارة الموجودة حاليًا بعد حصرها. تبقى حماية البيانات والصلاحيات على Supabase، لا على إخفاء الأزرار فقط.

## 5. البيانات والوسائط والأمان
- نفس Supabase الخارجي `matjer_ibb` ونفس الحسابات والبيانات والتخزين؛ لا ترحيل إلى Lovable Cloud ولا حذف بيانات.
- الحفاظ على قواعد الصلاحيات وفحص الهاتف واستدعاءات البحث الآمنة الحالية.
- إعداد متغيرات التطبيق العامة دون تضمين مفاتيح خادم أو service-role.
- استبدال استخدامات المتصفح وCapacitor ببدائل الهاتف: الموقع، اختيار الصور والفيديو، الروابط، التخزين، ومتابعة الأخطاء.
- الحفاظ على شرط إزالة صوت الفيديو عند الرفع؛ تحديد طريقة متوافقة مع Expo واختبار الملف الناتج فعليًا. إن احتاجت مكتبة أصلية، تُدرج ضمن development build ولا يُدّعى دعمها عبر Expo Go.
- نقل تفضيلات الإشعارات والوظائف الموجودة؛ لا إضافة خدمة إشعارات جديدة أو ميزات دون طلب.

## 6. التحقق والتسليم
- فحوص اعتماديات Expo والأنواع واختبارات للقواعد الأساسية: العملات، البيع/الإيجار، الهاتف، التصنيفات والصلاحيات.
- تجربة الرحلات الأساسية ببيانات حقيقية عندما تكون جلسة اختبار مخولة متاحة: الدخول ← استكمال الحساب ← المنتجات؛ الإضافة ← القراءة مجددًا؛ المفضلة؛ الموظفون؛ الإدارة.
- اختبارات الأجهزة تشمل Google وروابط العودة والموقع والوسائط والإيماءات والوضعين الفاتح والداكن. أي اختبار لا يمكن تشغيله هنا يُذكر صراحةً كغير متحقق.
- تسليم المصدر دون مفاتيح خاصة أو مجلدات اعتماديات أو نواتج بناء، مع دليل عربي، وملف إعدادات نموذجي، وقائمة الإعدادات الخارجية والخطوات المتبقية.

## التفاصيل التقنية
- React Native + إصدار Expo مستقر ومتوافق وقت التنفيذ، TypeScript وExpo Router.
- مكتبة مكونات أصلية ذات ثيم موحد وتوكنات مشتركة، لا نقل shadcn/HTML إلى الهاتف.
- Supabase JS مع تخزين جلسة مناسب للجوال؛ React Query لتزامن البيانات والمفضلة.
- بدائل أصلية مدعومة للصورة والفيديو والموقع والروابط والتعامل مع الأخطاء؛ لا استخدام مكتبات DOM للوظائف الأصلية.
- إعداد EAS Build لنسخة Android قابلة للتثبيت ونسخ إنتاج Android/iOS، دون تشغيل بناء مدفوع أو نشر تلقائيًا.

## ما يلزم منك خارج الكود
إعداد حساب Expo/EAS، وتوقيع Android، وحساب Apple Developer عند بناء نسخة iOS للتوزيع، وإعداد روابط Google وSupabase الخاصة بالتطبيق. قد يطلب البناء الأول إنشاء بيانات التوقيع أو الموافقة عليها، وقد تترتب رسوم على الخدمات أو حسابات المتاجر.

بعد هذه الإعدادات والاختبارات يصبح هدف «أشغّل أمر البناء فقط» واقعيًا للبناء المتكرر؛ أما التوقيع والمراجعة والنشر في المتاجر فليست أشياء يُنجزها المصدر وحده.
