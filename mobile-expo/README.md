# متجر إب — React Native + Expo

مشروع أصلي مستقل لـ Android وiOS. الموقع الحالي لم يُستبدل، والربط بنفس Supabase الخارجي `matjer_ibb`.

## التشغيل والبناء

المتطلبات: Node.js LTS، Bun أو npm، وحساب Expo. لبناء محلي: Android Studio/JDK لنظام Android، أو macOS/Xcode لنظام iOS.

```bash
cp .env.example .env
bun install --frozen-lockfile
bun run test
bun run typecheck
bunx expo-doctor
bunx eas-cli login
bunx eas-cli init
```

ضع معرّف مشروع EAS الناتج في `EXPO_PUBLIC_EAS_PROJECT_ID` داخل `.env`، واضبط نفس المتغيرات العامة في بيئة EAS. عنوان Supabase ومفتاحه المنشور في الملف النموذجي معلومات عامة، وليسا مفتاح خدمة؛ لا تضع service_role أو أسرارًا في متغيرات EXPO_PUBLIC.

البناء القابل للتثبيت على Android:

```bash
bunx eas-cli build --platform android --profile preview
```

الإنتاج:

```bash
bunx eas-cli build --platform android --profile production
bunx eas-cli build --platform ios --profile production
```

النسخة تستخدم وحدة أصلية لإزالة الصوت من الفيديو، لذلك يلزم **development build** أو نسخة EAS؛ ليست نسخة Expo Go. للتطوير المحلي:

```bash
bun run android
# على macOS فقط:
bun run ios
# بعد تثبيت development build:
bun run start
```

Expo Web مخصص لفحص العرض فقط؛ اختيار فيديو جديد فيه يفشل بأمان لأن إزالة الصوت تتطلب التطبيق الأصلي. الموقع الأصلي يحتفظ بآلية الفيديو الخاصة به.

## Google وروابط العودة

في Supabase Authentication → URL Configuration أضف:

```text
matjeribb://auth/callback
matjeribb://auth/callback?type=recovery
```

لا تستبدل Site URL للموقع. Google يستمر باستخدام callback الخاص بـ Supabase؛ التطبيق يستقبل رابط العودة أعلاه. اختبر رابط تأكيد البريد واستعادة كلمة المرور على الجهاز. لا تُغيّر إعدادات تأكيد البريد أو الربط التلقائي للهويات دون قرار صريح. إرسال OTP ما زال معطّلًا؛ التطبيق لا يغيّر phone_verified.

## الوظائف المنقولة

- حسابات Supabase الحالية: Google، البريد وكلمة المرور، تأكيد البريد، الاستعادة، جلسة محفوظة في SecureStore، خروج محلي أو من جميع الأجهزة.
- استكمال الاسم الأول والأخير والهاتف الفريد +967 والموقع، مع إمكانية تسجيل الخروج وفتح إعدادات الأذونات.
- المنتجات: بحث، تصنيفات متداخلة، مدينة، بيع/إيجار، عملة YER/SAR/USD، سعر وترتيب، تفاصيل، معرض تكبير بالإيماءات، فيديو، اتصال وWhatsApp ومشاركة.
- المفضلة المتزامنة، الحساب والصورة والموقع والأمان والتفضيلات، العربية/الإنجليزية واتجاه RTL، فاتح/داكن، صندوق الإشعارات والتنبيهات المحلية عند منح الإذن.
- التاجر: المتاجر المتاحة حسب العضوية، المنتجات وإجراءاتها وحقولها الديناميكية ووسائطها، موظفون وبحث هاتف وصلاحيات، إعدادات ملف التاجر.
- الإدارة: منتجات وحالات، حسابات وأدوار، تصنيفات وتداخل وحقول وترتيب، تعيين مشرفين، إشعارات للمحددين أو الحسابات المتاحة.
- Sentry اختياري عبر EXPO_PUBLIC_SENTRY_DSN دون جمع PII افتراضيًا. لا تُحفظ Expo push tokens لأن الخادم الحالي غير موثّق لدعمها.

الشعار داخل التطبيق هو Building2 الخطي بلا خلفية، مع لون الثيم. أيقونات تثبيت الهاتف لها خلفية للوضوح.

## حدود الخادم الحالي — لا تُخفى كنجاح

حافظ النقل على الصلاحيات الحالية دون تغيير قاعدة البيانات:

1. سياسات profiles الحالية تسمح بقراءة المدير العام لجميع الحسابات، لكن لا توجد سياسة UPDATE للمدير على ملفات الآخرين؛ لذلك إجراء تعليق الحساب قد يُرفض. حل ذلك يحتاج سياسة خادم معتمدة واختبارًا متعدد الأدوار، لا إخفاء الخطأ.
2. can_manage_employees موجود في العميل وRPC القراءة، لكن سياسة كتابة merchant_employees الحالية تقتصر على المالك/المدير. موظف مفوّض قد يُرفض عند تغيير الموظفين.
3. قراءة المنتجات غير النشطة لموظف ليست مضمونة بسياسة SELECT الحالية، رغم وجود صلاحيات تعديل؛ قد يظهر الحفظ مرفوضًا أو لا يمكن قراءة نتيجته. يلزم اختبار أو تعديل خادم معتمد.
4. مسؤول الإشعارات/الأقسام لا يملك بالضرورة قراءة جميع profiles؛ قوائم المستلمين/التعيين تعكس فقط البيانات المسموح بها، ولا يدّعي التطبيق إرسالًا إلى حسابات لم تُقرأ.
5. تعليق المستخدم بوابة واجهة، وليس ضمانًا أن كل سياسة خادم تمنع المستخدم الموقوف. لا تدّعي حماية خادم غير موجودة.
6. حفظ الأدوار طلبان مستقلان (إضافة ثم إزالة)، وليس معاملة ذرية؛ عند خطأ جزئي تُعاد القراءة ويظهر الخطأ. يمنع التطبيق إزالة دور المدير العام عن نفسه.
7. بيانات المتجر هي ملف التاجر الحالي، وليست كيانًا جديدًا لمتاجر مستقلة. تعديل النبذة/الموقع/الرابط يحدّث ذلك الملف، كما في الموقع.
8. القوائم تستخدم حد 1000 سجل مطابقًا لقيود الاستعلام الحالية؛ يلزم ترقيم صفحات إذا تجاوزت البيانات هذا العدد. النصوص القانونية المحلية موجزة وواقعية وتحتاج اعتماد المالك قبل إصدار المتاجر.

## التحقق قبل إصدار المتاجر

راجع `VERIFICATION.md`. فحص الأنواع أو تصدير JavaScript ليس بناء Kotlin/Swift أو تجربة جهاز. هنا لا تتوفر جلسة مخولة للخادم الخارجي ولا Xcode/Android SDK؛ لذلك لا تُعد الرحلات المسجّلة أو إزالة الصوت أو التوقيع أو الجاهزية للمتاجر متحققة.

أول بناء يتطلب إعداد توقيع وحسابات Expo/Google/Apple، وقد توجد رسوم. بعد إعدادها واختبارات الجهاز يمكن تكرار أمر البناء فقط؛ مصدر الكود لا ينفذ التوقيع أو مراجعة المتاجر تلقائيًا.
